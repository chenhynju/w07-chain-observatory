# Portfolio engineering rules

Continue the existing project; do not reinitialize it or replace pinned toolchains blindly.
All implementation, tests, commits and pushes must originate in the canonical WSL Linux working tree. Windows is a review mirror. Preserve differing files and Git history before resolving conflicts in favor of WSL content. Follow docs/deployment/workspace-workflow.md.
Use evidence-backed PASS/FAIL/BLOCKED/NOT_RUN. Freeze source hashes and Git commit for security reviews; label reports AI-Assisted Self-Assessment. Never claim independent audit or owner mastery from generated material. Do not commit .env, runtime keys/state, RPC credentials or signing material.
The current user authorizes this project's GitHub archive, public testnet and Vercel delivery. No mainnet, real funds, or new paid resources. Final Vercel/Cloudflare configuration is coordinated across the five portfolio projects. Existing service state, branches and deployments must be preserved.
